# 投流体检

一个分析广告报表的网页工具。把亚马逊、巨量千川、小红书聚光 / 乘风后台导出的报表传上去，它会列出哪些搜索词、计划或素材在亏钱，哪些值得加预算，并写明每条判断的依据。

所有计算都在浏览器里完成，网页不联网，不上传、不保存你的报表。

## 使用步骤

### 1. 从广告后台导出报表

| 平台 | 报表 | 导出位置 |
|---|---|---|
| 亚马逊 | 商品推广搜索词报告 | 广告 → 广告活动管理 → 衡量和报告 → 赞助广告报告 → 创建报告，广告类型选“商品推广”，报告类型选“搜索词”，建议选最近 30–60 天 |
| 巨量千川 | 搜索词 / 关键词报表 | 数据 → 搜索广告相关报表 → 下载数据表格，建议最近 14–30 天 |
| 巨量千川 | 计划 / 素材 / 商品报表 | 数据 → 全域推广数据（或标准推广数据）→ 选择维度 → 下载数据表格，建议最近 7–30 天 |
| 小红书 | 关键词 / 搜索词报表 | 聚光或乘风 → 数据报表 → 按关键词或搜索词维度下载 |
| 小红书 | 计划 / 笔记报表（有成交） | 乘风或聚光 → 数据报表 → 计划、单元或笔记维度，自定义列里勾选支付订单数和支付金额 |
| 小红书 | 笔记种草报表（没有成交） | 聚光 → 数据报表 → 笔记维度下载 |

支持 xlsx、xls、csv。千川和小红书的表头是按公开资料整理的，还没有用真实导出文件逐列核对过，上传后请检查第 2 步的列对应。

### 2. 上传并核对列

打开网页，选平台，上传文件。工具会自动识别每一列是什么，识别不对的可以手动改。没有报表的话，可以先点“用模拟数据看看效果”。

### 3. 填参照线

三选一：

- **填成本，算保本线（推荐）**
  - 亚马逊：售价、采购及头程成本、FBA 配送费、销售佣金，其他每单成本选填
  - 千川 / 小红书：客单价、商品成本、快递费、平台扣点、退货率（没有退货填 0），达人佣金选填
- **直接填目标**：目标 ACoS 或目标 ROI；种草笔记填目标互动成本
- **用账户平均作参照**：什么都不填，和整份报表的平均效率比

再填一段产品描述（标题和卖点即可），用来粗略判断搜索词和产品是否相关。

### 4. 看报告、导出清单

报告按“确定低效 / 疑似低效 / 表现优秀 / 数据不足 / 正常”分组，点开任意一行可以看到具体数字和判断理由。可以导出两个 CSV：

- 导出全部结论：每一行的数据、建议和理由
- 导出否定词清单：建议否定的搜索词

工具不会改动你的广告。要否定的词需要你自己到广告后台添加；亚马逊批量上传需要广告活动 ID，导出的清单里只有名称，需要自己对应。

## AI 相关性判断：用你自己的 AI 账号

工具本身不接任何 AI 接口。如果想让 AI 帮忙判断“这个搜索词和我的产品是否相关”：

1. 在报告页点“复制 AI 相关性判断提示词”
2. 粘贴到你自己在用的 DeepSeek、Kimi、ChatGPT 等对话框里
3. 根据 AI 的回答，再决定哪些词要否定

提示词里只有搜索词和你填的产品描述，没有花费、订单等数字。是否相关只是参考，AI 也会判断错。

### 想在自己部署的版本里直接调用 AI 接口

需要自己开发，大致步骤：

1. **准备 API 密钥**：在 DeepSeek 等服务商开通接口并拿到密钥。密钥只能放在你自己的服务器上，不能写进网页代码，否则任何打开网页的人都能看到。
2. **写一个服务端中转**：网页把搜索词和产品描述发给你的服务器，服务器带上密钥调用 AI 接口，再把结果返回网页。提示词可以复用 `src/core/export.ts` 里的 `aiPrompt()`。
3. **放开网页的联网限制**：`vite.config.ts` 默认把 `connect-src` 设为 `'none'`，网页连不了任何服务器。需要改成允许你的中转地址。
4. **更新隐私政策**：说明会把哪些内容发给谁，并在发送前让用户确认。`docs/legal/privacy.md` 目前写的是“不联网”，接入后必须改。
5. **加上调用限制**：按 IP 限制频率和每日次数，并在服务商后台设置消费上限，防止被人刷接口。

如果只是批量处理，也可以用下面的命令行版输出 JSON，再交给你自己的脚本去调用 AI。

## 本地运行和部署

需要 Node 22.12 或更高版本。

```bash
git clone https://github.com/bulijiojio99/ad-checkup.git
cd ad-checkup
npm install --legacy-peer-deps
npm run dev        # 本地打开 http://localhost:5173
npm test           # 运行测试
npm run build      # 生成 dist/ 目录
```

`dist/` 是纯静态文件，可以放到 GitHub Pages、Nginx 或任何静态托管上。放到自己网站上的方法见 [docs/integration.md](docs/integration.md)。

## 命令行版

```bash
npm run build:cli
node dist-cli/ad-checkup.mjs 报表.csv --platform amazon --price 45.99 --cost 14 --fba 7.2 --referral 15 --product "产品标题和卖点"
node dist-cli/ad-checkup.mjs 千川.xlsx --platform douyin --price 89 --cost 28 --shipping 4 --platform-pct 5 --return-rate 35 --negatives 否定词.csv
```

常用参数：

- `--platform`：`amazon`、`douyin`、`xiaohongshu`
- 成本：亚马逊用 `--price --cost --fba --referral`（`--other` 选填）；千川、小红书用 `--price --cost --shipping --platform-pct --return-rate`（`--commission` 选填）
- 直接填目标：`--target-acos`、`--target-roi`、`--target-cpe`
- `--product`：产品描述
- `--json`：输出完整结果；`--csv 文件名`：导出全部结论；`--negatives 文件名`：导出否定词清单

## 判断方法

1. 根据成本算出保本 ACoS（亚马逊）或保本 ROI（千川、小红书，计入退货率），也可以用你填的目标或账户平均值作参照。
2. 对每一行做统计检验：有点击数据的用二项分布，“假如它其实能保本，出现这么少订单的概率是多少”；没有点击数据的素材报表按花费做泊松检验；种草笔记按互动数检验。
3. 概率低于 5%、并通过多重比较校正的，归为“确定低效”；5%–20% 归为“疑似低效”；点击太少的归为“数据不足”，并给出大约还需要多少点击。
4. 把搜索词拆成单词累计，找出在多个搜索词里都不出单的词根，适合加否定词组。
5. 客单价按“这一行 → 所在广告组 → 全账户”加权估计，订单少的行更多参考上一层。本身已经达到参照线的行，不会被判为低效。

`tests/simulation.test.ts` 用模拟账户验证了误判率：刚好保本的词被判为亏损的概率不超过 5%，“确定低效”里实际赚钱的词不超过 10%。

## 局限

- 结论基于过去的数据，不代表以后的效果。
- 千川、小红书的表头还需要用真实导出文件核对。
- 相关性粗判只看字面，用词不同但意思相关的搜索词可能被判为部分相关。
